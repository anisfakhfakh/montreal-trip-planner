# testing/

This directory contains a route-validation harness, not standard unit tests. It batch-runs a fixed set of real-world origin/destination pairs against the live app. Optionally, it can also run these against Google as an independent oracle. This allows routing or scoring changes to be sanity-checked against actual trips rather than just confirming the endpoints return a 200 status.

| File | Purpose |
|---|---|
| `routes.json` | Contains 36 canonical routes (`id`, `from`, `to`, coordinates, `defaultTime`, `dayType`, `allowedModes`, `focus`). The `focus` field explains what the route tests, such as a metro-only baseline or a late-night closure edge case. |
| `validate_routes.py` | Batch-runs every route in `routes.json` against a live `/api/plan_trip` endpoint (requires `app.py` to be running) and writes the results to a JSON file. The `--with-google` flag additionally live-queries `services/google_routes_client.py` for a three-way comparison between this app, Google Transit, and a Google BIXI maps link. This uses real Google API calls, so it is opt-in. See the module's docstring for full usage and flag details. |
| `google_compare.py` | Handles the Google-side leg reconstruction and formatting. Imported by `validate_routes.py` for the `--with-google` path. |
| `dev_test_weather.py` | An unrelated development helper, not part of the validation harness. Runs the real app while forcing the weather to a specific scenario, allowing you to test the harsh-weather UI without waiting for actual bad weather. Check its docstring for usage instructions. |
| `route_validation_log.html` | A standalone dashboard for reviewing results, deployed separately as a static HTML page (live at [claude.ai/code/artifact/648f84a8-fa54-41b1-a291-ce7e92bea8a1](https://claude.ai/code/artifact/648f84a8-fa54-41b1-a291-ce7e92bea8a1)) and not served by the Flask app. **The embedded `ROUTES` array inside is a hand-maintained mirror of `routes.json`.** If you edit `routes.json`, you must mirror the exact change in this file's `ROUTES` array and redeploy to prevent the dashboard from drifting out of sync. Includes an "Import script results" button to load the JSON file generated by `validate_routes.py` — this writes to that browser's `localStorage` only, so it doesn't affect what other visitors see. **The embedded `BAKED_RESULTS` array is a baked-in snapshot of a past `validate_routes.py --with-google` run**, used to seed a brand-new visitor's first view instead of showing an all-"Not tested" page; it never overwrites a browser that already has its own saved `localStorage` state. Regenerate it (replace the array with a fresh run's output JSON) and redeploy whenever you want visitors without prior local edits to see up-to-date numbers. |
| `addresses.md` | Manual reference containing real Google Maps addresses for each route's origin and destination. |
| `bixi_links.md` | Manual reference of Google Maps bicycling-directions links per route. Used for cross-checking BIXI-only itineraries, as Google's bike-share integration only provides clickable links, not an API. |
| `results/` | Gitignored directory containing dated run output from `validate_routes.py`. These files are not committed; regenerate them by running the harness. |

## Running it

```bash
python app.py                              # In one terminal: the harness needs a live server
python testing/validate_routes.py          # In another terminal
python testing/validate_routes.py --ids 6,14,35 --with-google
